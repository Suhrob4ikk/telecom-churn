# Отток абонентов мобильного оператора: SQL-аналитика в Oracle и ML-модель

Учебный проект, который повторяет задачи аналитика и ML-инженера в телеком-операторе:
SQL-запросы и витрина данных в **Oracle**, отчёт в **Excel**, анализ в **Jupyter** и
**модель оттока** на градиентном бустинге с расчётом экономики удержания.

## Часть 1. Аналитика оператора (Oracle SQL)

> ⚠️ Данные **синтетические**: их генерирует [`src/generate_synthetic.py`](src/generate_synthetic.py)
> по структуре данных мобильного оператора. Реальных данных абонентов в проекте нет.

7 таблиц: абоненты (20 000), тарифы, салоны, помесячное потребление (163 тыс. строк),
продажи в салонах (46 тыс.), маркетинговые акции и контакты с целевой и контрольной группами.

| Вопрос бизнеса | SQL | Что нашлось |
|---|---|---|
| Как меняются продажи в салонах? | `GROUP BY`, `LAG` по месяцам | пики в декабре и марте (Новый год, Навруз) |
| Как используются тарифы? | `JOIN` трёх таблиц, ARPU | ARPU на ~30% выше абонплаты, пакет интернета используется на 65% |
| Работают ли акции удержания? | target vs control | отток за 3 мес. ниже на **9–12 п.п.**, χ² p < 0,001 |
| Где уходят абоненты? | подзапрос + `AVG() OVER ()` | 2 салона Худжанда: отток в 1,4–1,5 раза выше среднего по сети |
| Можно ли заметить уход заранее? | витрина с оконными функциями | за месяц до ухода трафик и пополнения падают на ~25% |

* [`sql/01_schema.sql`](sql/01_schema.sql): схема с ключами и CHECK-ограничениями
* [`sql/02_mart.sql`](sql/02_mart.sql): витрина «абонент × месяц» для ML; признаки считаются только по прошлым месяцам, без заглядывания в будущее
* [`sql/03_analysis.sql`](sql/03_analysis.sql): аналитические запросы
* [`reports/telecom_report.xlsx`](reports/telecom_report.xlsx): Excel-отчёт с графиками
* [`notebooks/01_operator_analytics.ipynb`](notebooks/01_operator_analytics.ipynb): визуализация, проверка гипотез, рекомендации

## Часть 2. Модель оттока (реальный публичный датасет)

Данные: [IBM Telco Customer Churn](https://github.com/IBM/telco-customer-churn-on-icp4d), 7 043 абонента.

| Модель | ROC-AUC (CV) | ROC-AUC (тест) | PR-AUC | Lift@20% |
|---|---|---|---|---|
| Логистическая регрессия (бейзлайн) | 0,820 ± 0,013 | 0,826 | 0,621 | 2,41 |
| **LightGBM** | **0,831 ± 0,013** | **0,841** | **0,649** | **2,45** |

**Экономика:** при допущениях «предложение = скидка в один месяц, удерживает 30% уходящих,
удержанный приносит ещё 12 месяцев» выгоднее всего охватить 38% абонентов, отсортированных по
*риск × платёж*. Прибыль на тестовой выборке — **35 тыс. $**, это в 4,6 раза больше, чем при предложении всем.

[`notebooks/02_churn_model.ipynb`](notebooks/02_churn_model.ipynb)

## Как запустить

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
python src/generate_synthetic.py      # синтетические CSV
python src/load_oracle.py             # схема + загрузка в Oracle + витрина
python src/build_report.py            # SQL-запросы -> Excel-отчёт
python src/build_notebooks.py         # выполнить ноутбуки
```

Для Oracle нужен файл `.env` (в git не попадает):

```
ORACLE_USER=churn
ORACLE_PASSWORD=...
ORACLE_DSN=localhost:1521/FREEPDB1
```

Проверено на Oracle Database 23ai Free, Python 3.13.
